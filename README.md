# Ent303 Rise

## Windows 版已加入

Windows 用户双击项目根目录的 `Start_RISE_Windows.cmd` 打开小猫陪练。包含宽松动作检测、自动开始、每组 5 金币、持久化钱包、商店与背包；支持本机离线识别。运行方式、19 项已通过测试和版本范围见 [Windows/README.md](Windows/README.md)。

## 新增：小猫陪练 / 运动赚金币

主窗口点击「运动赚金币」进入。可选三种摄像头识别动作与 1–20 组，每个动作每组 3 次，完成一组自动奖励 5 金币，可用于原有商店。使用补充 UI 素材里的摇尾小猫与金币动画。

运行、验收、改动说明与当前限制见 [MOVEMENT_README.md](MOVEMENT_README.md)。本次在 Windows 编写，尚未通过 Mac 编译与摄像头实测。

一个 macOS 桌面小工具，解决久坐问题：记录连续工作时长，到点提醒你起来活动，并给一条具体建议。

## 当前状态：可测的 MVP

**两种提醒方式，在设置里切换：**

| 方式 | 判断依据 |
|---|---|
| **自动检测**（默认） | 读取系统空闲时长，无需任何权限。空闲 ≤ 2 分钟算在工作，≥ 5 分钟算已离开并清零 |
| **手动确认** | 两个图标手动声明：点「在电脑前」开始计时，点「去活动」停止并清零 |

**提醒间隔：**

- **时 / 分 / 秒** 三段独立输入框，可自由组合（如 `1 时 30 分 0 秒`）
- 编辑后按 **回车** 或 **点击卡片空白处** 提交；提交时会规范化（如 `90 分` → `1 时 30 分`）
- 全部填 0 或清空时不生效，自动回退到上一个有效值
- 右侧 **上下箭头** 按分钟增减，保留已填的秒数
- 另有 **「10 秒测试」** 按钮，仅用于技术验证，不是正式选项；进入后可用「退出测试」回到 45 分钟
- 测试态下目标值与设置行会变橙色，避免与正式配置混淆

**其它已实现：**

- ✅ 连续工作计时、进度条、距下次提醒的倒计时
- ✅ 12 条建议池，随机且不连续重复
- ✅ 标题栏有 **× 退出按钮**
- ✅ 菜单栏常驻：显示/隐藏、立即提醒、退出
- ✅ 无 Dock 图标，透明悬浮窗，可拖动

## 缩略图标

鼠标离开界面 **5 秒**后，窗口自动缩成 RISE 圆形图标，停靠在详情窗口**右下角**的位置。
标题栏的 **−** 按钮也可以随时手动缩略。

- **拖动**：按住图标拖动可移动到任意位置
- **点击**：恢复详情界面，以图标右下角为锚点向左上展开
- 正在编辑时长输入框、或有提醒未处理时，**不会**缩略
- 提醒触发时会自动展开，确保你能看到

> 悬停判定用 **0.4 秒轮询鼠标坐标**，而不是 SwiftUI 的 `onHover`。
> 后者在窗口成为 key window 后退出事件可能不触发，会导致"窗口被选中时永远不缩略"。

## 运行

```bash
./build.sh
open build/Ent303_Rise.app
```

需要 macOS 13+ 和 Command Line Tools。不需要完整 Xcode。

> 本机 `swift build`（SwiftPM）因 CLT 与 SDK 版本错位会 abort，
> 所以 `build.sh` 直接调用 `swiftc` 并显式指定一个匹配的 SDK。

## 怎么退出

- 界面右上角 **×**
- 菜单栏的站立小人图标 → 退出
- 终端 `pkill -f Ent303_Rise`

> 它是独立的 macOS 进程，不是 DSH 插件，**退出 DSH 不会关掉它**。
> `Cmd+Q` 也不行——没有 Dock 图标，不是前台应用。

## 怎么测

1. 打开 app，屏幕右下角出现悬浮窗
2. 默认自动检测，头部显示「正在电脑前工作（空闲 N 秒）」并开始计时
3. 点 **「10 秒测试」**，等 10 秒看提醒是否准点弹出
4. 点 **我起来了** → 提醒关闭、计时归零
5. 在输入框里填 **1**，验证自定义间隔生效
6. 切到 **手动确认** → 出现两个图标，手动切换状态
7. 什么都不动等 5 分钟 → 自动模式显示「检测到你已离开，计时已清零」

调试参数：

```bash
open build/Ent303_Rise.app --args --demo-reminder        # 启动 1 秒后弹一条提醒
open build/Ent303_Rise.app --args --demo-test-interval   # 以 10 秒间隔启动
```

## 开屏动画（第 2 页）

素材：`Resources/pet.gif`（动画）、`island.png`（平台）、`cat_final.png`（静态猫）。

编排逻辑：

1. GIF **只播一遍**，逐帧驱动（不是 NSImageView 自播），因此能精确知道当前相位
2. 字母开始下沉（第 4 帧）→ 平台从容器右侧外滑入，ease-out
3. 抵达「凝结帧」（第 44 帧）→ 平台停住，此时猫正好落在平台宽度的 30% 处
4. 播放结束（6.58s）→ 隐藏 GIF，用静态猫顶在**完全相同的位置与尺寸**
5. 播放期间禁止自动缩略，结束后重新开始 5 秒倒计时

构图比例来自设计稿测量：

| 比例 | 值 |
|---|---|
| 猫中心 X / 平台宽 | 0.30 |
| 猫宽 / 平台宽 | 0.34 |
| 平台宽度 / 容器宽 | 0.62 |

构建期由 `tools/build_intro.py` 处理素材：拆帧、算相位帧号、裁切平台与静态猫，
输出 `Resources/intro/`（含 `meta.json`）。改 GIF 后重新 `./build.sh` 即可。

> 测试阶段：每次切到第 2 页都会重播这段动画。

## 平台下方菜单

平台下方一排：**播放 / 专注 / 商店 / 背包 / LOGO**（顺序同设计稿）。

- **播放键是展开/收起开关**：展开时三角朝右，收起时水平镜像朝左
- 收起后只保留开关和 LOGO，其余三个按钮以缩放+淡出过渡消失
- 动画用 spring（response 0.36 / damping 0.78）
- 整排右对齐到平台右边缘，随平台左移一起定位

尺寸按参考图测量的比例（相对平台宽度）：

| 元素 | 比例 |
|---|---|
| 按钮直径 | 0.160 × 平台宽 |
| LOGO 直径 | 0.218 × 平台宽（约为按钮的 1.36 倍） |
| 按钮间距 | 0.32 × 按钮直径 |
| 与平台底边间隙 | 0.03 × 平台宽 |
| 右端超出平台 | 0.08 × 平台宽 |

整排**右对齐**到平台右边缘，因此最左按钮自然落在平台左侧以内（约 +0.086 平台宽），
LOGO 右侧与平台右边缘齐平。

> 三个功能按钮目前只是占位，点击无行为，等接入具体功能。

## 提醒弹窗（第 2 页右侧）

第 2 页为左右分栏：**左侧宠物（248pt）+ 右侧提醒位**，窗口宽度 320 → 440。

到点提醒时右侧出现卡片，包含：

- 顶部小字：`已连续 N 分钟`
- 建议标题与说明（取自建议池）
- **我起来了**（面板黄 `#FFCE63` 胶囊）/ **再等等**（描边胶囊）

配色取自现有美术素材：奶油底 `#FFFAE0`、深褐文字 `#5C4F4D`、面板黄按钮。
无提醒时该区域留空，不占位不遮挡。

## 商店 / 背包面板

点击 **购物车** 或 **书包** 图标，在平台上方弹出面板（位置比例参考设计稿）。

- 面板素材：`Resources/panel/{food,plant,beds,accs}.png`，每张对应一个激活 Tab
- 顶部 **FOOD / PLANT / BEDS / ACCS** 四个 Tab 可点击切换
- 购物车打开时默认 FOOD，书包打开时默认 ACCS；再点一次收起
- 弹出/收起用 spring + 缩放淡入

Tab 命中区由素材实测得出（相对面板宽度）：起点 0.0635，每个宽 0.0747，y 在 0.245 起。

### 购买与背包

- **点击格子**即购买，格子中央播放金币动画（`Resources/coin.gif`，92 帧 / 2.4 秒，只播一遍）
- 金币尺寸取格子内容宽度的 35%，并按 GIF 里金币占画布 27% 反推视图大小，保证与物品同尺度
- **FOOD / PLANT**：可重复购买，物品不消失
- **BEDS / ACCS**：一次性购买；买完该格留空，**下次打开面板时压缩重排**补上空位
- 购物车图标 → 商店模式；背包图标 → 背包模式（显示已拥有的物品）
- 同一图标再点一次收起面板

> 已购记录与金币余额都只存在内存里，重启应用会清空（测试阶段如此，后续需要持久化）。

### 金币余额

面板右上角显示「金币图标 + 数字」，**由代码绘制**——素材里那个位置只有一条胶囊，没有数字。

- 测试版初始 **20** 个
- 右上角**积分条长度**随余额变化（`coins / 20` 为满格），内缩 1.6pt 保留素材描边
- 每次购买扣 `itemPrice`（当前统一 1，可按分类配置）
- 余额不足时点击不会购买
>
> 背包里同一物品只显示一个，数量以右下角 `×N` 角标表示（1 个时不显示角标）。

### 物品格子与翻页

每个分类 **16 个物品 = 2 页 × 8 格**，素材在 `Resources/shop/<分类>/<分类>_NN.png`。

- 8 个格子的归一化位置由面板素材实测（4 列 × 2 行）
- **翻页按钮**：圆形的播放图标，右侧=下一页、左侧=上一页（左箭头由水平镜像得到）
- 第一页只显示右箭头，最后一页只显示左箭头，中间页两侧都有
- 每个 Tab 独立记住自己的页码

## 检查台

菜单栏图标 → **检查台**（`⌘I`），或启动时加 `--open-inspector`。

检查台和主面板共用同一个 `AppState`，用于技术测试与视觉素材检查：

- **运行状态**：检测方式、计时、进度、系统空闲、鼠标是否在窗口内、是否编辑中、是否有提醒、是否已缩略
- **操作**：立即提醒 / 我起来了 / 10 秒测试 / 退出测试 / 缩略为图标 / 展开详情
- **视觉素材**：猫形 S 融化动画的 8 个关键帧，可播放、单步、点缩略图跳转；另有 logo 预览

> 检查台打开期间会**禁止自动缩略**，方便你对照主面板观察。

## 待确认的设计问题

### ❓ UI 菜单右上角的进度条是什么功能（未定义）

**位置**：点击购物车 / 背包图标弹出的 UI 菜单（`Resources/panel/*.png`）的**右上角**——
一条胶囊形进度条（内部约 40% 被深色填充），右边紧挨一个黄色笑脸圆点。

**现状**：这两个元素都是**素材图片里画死的静态内容**，代码没有接任何逻辑，
也不随金币余额、页码、购买行为变化。

**待产品定义**：

1. 这条进度条表示什么数值？（库存？刷新倒计时？好感度？）
2. 黄色笑脸是否要跟着数值切换表情？
3. 需要它随什么事件变化（购买、翻页、时间、久坐时长）？

> 注：素材库 `~/Downloads/Arts- transparent/Status/` 里另有一套「胶囊 + 爱心/闪电」的
> 0%/60%/100% 三档图，那是**桌宠本体**的状态条，和上面这个 UI 菜单里的不是同一个东西。

## 已知局限

当前"是否在工作"只看全系统键鼠输入，不区分内容。
**看视频、读长文而不碰键鼠时，会被误判成"离开"**——后续需要结合前台应用或播放状态修正。

### ⚠️ UI 菜单 Tab 栏字符过小（未解决）

面板顶部 **FOOD / PLANT / BEDS / ACCS** 四个 Tab 的字符**约 5.2pt，肉眼几乎无法辨认**。

根因：Tab 栏直接来自素材图片，其高度只占面板高度的 3%，字号被素材比例锁死。

已验证过的方案与结果：

| 方案 | 效果 | 代价 |
|---|---|---|
| 窗口加宽到 400×640 | Tab → 6.7pt | 平台/猫/按钮全部放大 28%，窗口面积 ×4（已回退） |
| 面板改为用满内容宽度 | Tab → 5.2pt | 无（已采用） |
| 窗口加宽到 360 + 组件钉死尺寸 | 约 6.0pt | 窗口横向 +40pt（未实施） |
| **自绘 Tab 栏**（不用素材的 Tab 条） | 字号完全可控（可到 11pt） | 需要改 UI 实现（未实施） |

待决策：优先"自绘 Tab"（彻底解决），还是"加宽窗口 + 钉死组件尺寸"（改动小）。
